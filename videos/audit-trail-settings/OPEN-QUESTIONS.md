# Open questions: audit-trail-settings

Everything in the narration was read from the Orchard Core source at commit 92db4a83 (paths start from `src/`). The
points below could not be checked without a running site. A person confirms each one before the first take and writes
the answer next to it. None of them is stated in the narration as a fact, unless the entry says so.

## What the screen looks like

1. **Order of the tabs.** The tab names come from placement strings: "Events" (`OrchardCore.Modules/OrchardCore.AuditTrail/Drivers/AuditTrailSettingsDisplayDriver.cs:76`, no tab position), "Trimming" (`.../AuditTrailTrimmingSettingsDisplayDriver.cs:39`, position 0) and "Content" (`OrchardCore.Modules/OrchardCore.Contents/AuditTrail/Drivers/ContentAuditTrailSettingsDisplayDriver.cs:41`, position 5). Reading `OrchardCore/OrchardCore.DisplayManagement/Zones/ZoneShapes.cs:71-85`, `FlatPositionComparer.cs:152-158` and `OrchardCore/OrchardCore.DisplayManagement/Shapes/GroupShapes.cs:197`, the order should be Events, Trimming, Content, with the first tab active. The narration never states an order. The plan clicks every tab by its name. Confirm the order and that the page opens on Events after a save.
2. **Order of the categories** in the Events table. The categories come from a frozen dictionary (`OrchardCore/OrchardCore.AuditTrail.Abstractions/Services/Models/AuditTrailOptions.cs:10-16`), so the source does not fix whether Content or User is first. The narration says Content, then User; the plan tells the recorder to highlight them in that order whatever the page order is. Confirm the rows can be reached that way with `ScrollAsync`.
3. **Page heading.** `AuditTrailSettings.Edit.cshtml:4-8` clears the title and adds the heading "Audit Trail", and `OrchardCore.Settings/Views/Admin/Index.cshtml` adds a breadcrumb "Settings". Nothing in the narration depends on how they look together.
4. **Select all.** After "Login failed" is selected, the "Select all" checkbox of the User category should be checked by the script (`OrchardCore.AuditTrail/Assets/ts/audit-trail-settings.ts:11-25`). Confirm; the narration only mentions that each category has a Select all checkbox.
5. **List of user properties** on Settings, Security, User Audit Trail. It is built by serializing a new user (`OrchardCore.Users/AuditTrail/Controllers/AuditTrailAdminController.cs:49-53`), so the labels should be, in this order: AccessFailedCount, Email, EmailConfirmed, Id, IsEnabled, IsLockoutEnabled, LockoutEndUtc, LoginInfos, NormalizedEmail, NormalizedUserName, PhoneNumber, PhoneNumberConfirmed, Properties, RoleNames, SecurityStamp, TwoFactorEnabled, UserClaims, UserId, UserName. The narration relies on two facts: a property named Email is listed, and the password hash, reset token and user tokens are not (`OrchardCore.Users/AuditTrail/Handlers/UserEventHandler.cs:29-35`). Confirm both, and that no custom user settings appear with Custom User Settings disabled.
6. **Drop-down options.** Expected on the recording site: an empty option, ErasingRedactor, PartialAsteriskRedactor, Store (`OrchardCore.Users/Views/AuditTrailAdmin/Index.cshtml:24-31`). HmacRedactor is registered only when a key is configured (`OrchardCore.Users/AuditTrail/Startup.cs:47-50`), so it is absent. Confirm there are exactly these four options.
7. **Audit Trail list layout.** The plan's selectors accept the List and the Grid layout (`OrchardCore.AuditTrail/Views/AuditTrailAdminList.cshtml:29-37`). Confirm which one the site shows by default and that the client IP address badge is visible in it.
8. **Saving.** `OrchardCore.Settings/Controllers/AdminController.cs:126-127` suspends the release of the tenant when the input is invalid, which suggests that a valid save can reload the tenant. Time a save, and confirm that "Site settings updated successfully." stays on screen long enough for the end of `events-7` and `trim-4`. The plan allows `OffCameraAsync` for the wait.
9. **Client IP address.** On a local site the badge should show a loopback address. Confirm which one (`::1` or `127.0.0.1`) and that it is the only address that appears.
10. **Failed sign-in of an unknown name.** `OrchardCore.Users/Controllers/AccountController.cs:211-213` records the event with the typed name even when no such user exists. Confirm that an entry "Login failed" for `guest.visitor` appears, with the client IP address, once Login failed is on and the address setting is saved.
11. **The Page.** The Blog recipe defines the type "Page" (`OrchardCore.Themes/TheBlogTheme/Recipes/blog.recipe.json`). Confirm that the checkbox in the Content tab is labeled "Page", and that publishing a Page after clip `02-events` produces entries in the list.

## What the narration says that a person may want to verify

12. **Trimming schedule.** "By default, it runs once a day" follows the task attribute (`OrchardCore.AuditTrail/Services/AuditTrailBackgroundTask.cs:11-14`, schedule `0 0 * * *`). The Background Tasks feature, which stays disabled for the recording, can change a task's schedule. On a fresh site "Last run" reads "Never" until the first run; the narration says only that it shows when the task last ran.
13. **Snapshot behavior.** `users-4` says a snapshot is saved for Created, Updated, Enabled, Disabled and Confirmed events and appears as "User Snapshot" on the Details page, and that deleting a user removes that user's snapshots from earlier events (`UserEventHandler.cs:90-126`, `:231-237`, `:102-121`). To check it on a site: save Email with PartialAsteriskRedactor, create a user whose email is on `example.com`, and open Details of the Created event. The video does not show that panel (see the specification question about the User Snapshot).
14. **HmacRedactor.** `options-2` says HmacRedactor stores a hash of the value and is offered only when a key is configured. The first half comes from the documentation page of the Users module (section Audit Trail Integration), not from code in this repository, because the redactor itself is in a Microsoft library. Confirm it on a site configured for it, or reword the slide. The documentation says both `HmacRedactorOptions.Key` and `HmacRedactorOptions.KeyId` must be set; the code registers the redactor when the key is not empty and does not look at the key id (`OrchardCore.Users/AuditTrail/Startup.cs:47-50`), so the narration says only "a key". `options-2` also says ErasingRedactor "shows that the property had a value": the code skips a property whose value is empty (`UserEventHandler.cs:182-193`), so an empty string in a snapshot means the property had a value. Confirm on a site with a user whose email is set.
15. **Default user event data.** `users-1` says a user event stores the user's name and ID by default. The documentation says the same; in the code every user event sets a user name and a user ID (`OrchardCore.Users/AuditTrail/Models/AuditTrailUserEvent.cs`), except the failed sign-in of an unknown name, whose ID is empty.
