# Recording plan: Password and Lockout Options

A developer video. Ten steps are slides (drawn by `slides.py`, nothing to record). Seven steps are browser
recordings in three clips: `05-rules`, `06-signin` and `06-unlock`. Read `OPEN-QUESTIONS.md` first: it lists what
this plan assumes and a person must confirm on the first take.

Source references are `file:line` in `OrchardCMS/OrchardCore` (the checkout of the site, `main`), under `src/`.

## The site it needs

A fresh, throwaway site, never a production site, from a checkout of `OrchardCMS/OrchardCore`.

1. **Provision with Auto Setup** (`references/recording.md`), with these values, on `http://localhost:5010`:

   | Setting | Value |
   |---|---|
   | Site name | `Orchard Core` |
   | Recipe | `Blog` |
   | Time zone | `America/Los_Angeles` |
   | Database | `Sqlite`, in an `ORCHARD_APP_DATA` folder outside both repositories |
   | Admin user | `admin`, email `admin@example.com`, password `<password>` (the `VIDEO_PASSWORD` chosen outside git) |
   | Outbound calls | `HTTP_PROXY` and `HTTPS_PROXY` set to a dead address; the video needs no mail, SMS or external service |

   The Auto Setup variables are `OrchardCore__AutoSetup__Tenants__0__ShellName`, `...__SiteName`, `...__SiteTimeZone`,
   `...__AdminUsername`, `...__AdminEmail`, `...__AdminPassword`, `...__DatabaseProvider` and `...__RecipeName`
   (`docs/reference/modules/AutoSetup/README.md`). Do not record the Setup screen: no clip needs it.

2. **Apply the options the slides show, in the site's `Program.cs`.** Edit `src/OrchardCore.Cms.Web/Program.cs` of the
   throwaway checkout (the edit is never committed, to this repository or to the checkout's remote). Add
   `using Microsoft.AspNetCore.Identity;` and, after the `var orchardCore = ...AddSetupFeatures("OrchardCore.AutoSetup");`
   statement:

   ```csharp
   orchardCore.ConfigureServices(tenantServices =>
       tenantServices.Configure<IdentityOptions>(options =>
       {
           options.Password.RequireDigit = false;
           options.Password.RequireLowercase = true;
           options.Password.RequireUppercase = true;
           options.Password.RequireNonAlphanumeric = false;
           options.Password.RequiredUniqueChars = 3;
           options.Password.RequiredLength = 6;

           options.Lockout.AllowedForNewUsers = true;
           options.Lockout.DefaultLockoutTimeSpan = TimeSpan.FromMinutes(5);
           options.Lockout.MaxFailedAccessAttempts = 3;
       }));
   ```

   `OrchardCoreBuilder.ConfigureServices` runs for each tenant (`OrchardCore.Abstractions/Modules/Builder/OrchardCoreBuilder.cs:53`,
   documented for the MiniProfiler options in `docs/reference/modules/MiniProfiler/README.md`). These are the values of the
   slides `code-1`, `code-2`, `lockout-1` and `lockout-2`. Make the edit **before the first start**, so Auto Setup runs under
   the same rules.

3. **`VIDEO_PASSWORD` must satisfy these rules**: at least six characters, at least one lowercase and one uppercase
   letter, at least three different characters. Otherwise Auto Setup cannot create `admin`
   (`OrchardCore.Users.Core/Services/UserService.cs:136` calls `UserManager.CreateAsync` with the password).

4. **Features and settings**: nothing to enable. The Users module is part of the Blog recipe. The Blog recipe does not
   enable `OrchardCore.RateLimits`: leave it disabled (when enabled, the sign-in route allows 100 attempts per window and
   IP address, `OrchardCore.Users/Startup.cs:285`, which the few attempts of `06-signin` would not reach anyway). No
   option requires a confirmed email before the password check, so the unconfirmed email of `jamie` does not stop the
   failed attempts from counting. Leave the admin settings at their defaults; the Users list may show its row actions as an **Actions** button or as an ellipsis menu
   (`Admin/Views/AdminListActions.cshtml:31`, `AdminListActions-Menu.cshtml:24`), and the plan works with both.

5. **Seed data**: none outside the capture. The user is created on camera in `05-rules`:

   | Field | Value |
   |---|---|
   | User name | `jamie` |
   | Email | `jamie@example.com` |
   | Password | typed `jam` first (invalid on purpose), then generated by the **Generate password** button |

6. **Sign in once outside the capture**: `Recorder setup` with `VIDEO_USER_NAME=admin` and `VIDEO_PASSWORD`, which writes
   `state.json` (git-ignored). The admin password is never typed on camera.

## Order, dependencies and snapshots

Record in this order; each clip starts from the state the previous one left:

1. `05-rules` creates the user `jamie`, with lockout enabled (the user is created by `UserManager.CreateAsync` through
   Add User, never through a Users recipe step: `Recipes/UsersStep.cs:55` copies `IsLockoutEnabled` from the recipe, and
   the column defaults to false, `Migrations.cs:22`).
2. `06-signin` locks `jamie` out. It needs `jamie` from `05-rules`, and runs **signed out**.
3. `06-unlock` needs the lockout of `06-signin`, which lasts five minutes (`DefaultLockoutTimeSpan`). Record both in
   one command, `Recorder record 06-signin 06-unlock`. If more than five minutes pass, the **Locked** badge is gone:
   record `06-signin` again first.

All three clips change the site. Stop the site and copy `App_Data` and `state.json` aside after Auto Setup and the
`Recorder setup` sign-in; restore that copy (and start the site again) before every full take, and before taking
`05-rules` or `06-signin` again.

`06-signin` has to start without the admin's session: create its scene with a storage-state path that does not exist
(`Scene.StartAsync` uses the file only when it exists, `Scene.cs:109`), for example `Path.Combine(Scenes.Root, "signed-out.json")`.
`05-rules` and `06-unlock` use `state.json` as usual.

- `options-2`: four cards with the defaults: length, character rules, failed attempts allowed, lockout time.
- `options-3`: four cards: where Orchard Core uses the options (Setup, Add User, create/change/reset, sign-in).
- `code-1`: the `Startup` class with the six Password options, and three notes.
- `code-2`: the same code, the six option lines bright, and a note for each kind of option.
- `lockout-1`: the `Startup` class with the three Lockout options.
- `lockout-2`: the same code, the `AllowedForNewUsers` line bright.

- `where-3`: `appsettings.json` with the `OrchardCore` section, and notes on environment variables and tenants.

## Clip `05-rules` (chapter 05, steps `rules-1`, `rules-2`, `rules-3`)

Starts on `/Admin` (the dashboard), signed in as `admin`, with the admin menu collapsed. Open it with
`scene.OpenAsync("/Admin")`, not recorded. Selectors below stand for `scene.Page.Locator(...)`. The form's field names
come from the display driver prefix `User` (`DisplayManagement/Handlers/DisplayDriver.cs:75-84`, and
`[Bind(Prefix = "User.Password")]` at `Controllers/AdminController.cs:297`): check them once with `Recorder probe`.

`rules-1` (the narration is about 13 seconds)
- Click **Access Control** in the admin menu (label: `Users/AdminMenu.cs:27`), then **Users** (`AdminMenu.cs:30`); the menu
  items have the ids `accessControl` and `users`. Wait for the Users list.
- Click **Add User** (`a.create`, text `Add User`, `Views/UsersAdminListCreate.cshtml:7`) and wait for the form
  (breadcrumb **Create User**, `Views/Admin/Create.cshtml:4`).
- Type `jamie` in `[name='User.UserName']` (label **User name**, `Views/UserName.Edit.cshtml:4`), `jamie@example.com` in
  `[name='User.Email']` (**Email**, `Views/UserEmail.Edit.cshtml:4`), and `jam` in both `[name='User.Password']` and
  `[name='User.PasswordConfirmation']` (`Views/UserFields.Edit.cshtml:16,27`). Click `.password-toggle-button` (the eye icon),
  so the short value is readable.
- Visible when the narration ends: the **Create User** form with the user name, the email, and `jam` in both password
  fields, readable.

`rules-2` (about 13 seconds)
- Click **Save** (`button.save`, `Views/UserSaveButtons.Edit.cshtml:2`) with `ClickAndWaitForNavigationAsync`. Wait for the
  validation summary (`.validation-summary-errors`, `Create.cshtml:10`).
- Visible when the narration ends: the form again, and above it the summary with two messages, "Passwords must be at least 6
  characters." and "Passwords must have at least one uppercase character ('A'-'Z')." (`UserService.cs:313,319`). No message
  about a digit or a non-alphanumeric character. Nothing was created.

`rules-3` (about 9 seconds)
- Click **Generate password** (`.password-generator-button`, `Views/UserFields.Edit.cshtml:39`); both password fields fill in
  (`wwwroot/Scripts/user-editors/user-fields.js`, which reads the options from the button's `data-password-*` attributes).
  Click `.password-toggle-button` so the generated value is readable, hold for 1.5 seconds, then click **Save** with
  `ClickAndWaitForNavigationAsync`.
- Visible when the narration ends: the Users list with the notification "User created successfully."
  (`AdminController.cs:320`) and `jamie` in the list.

## Clip `06-signin` (chapter 06, steps `lock-1`, `lock-2`)

Signed out (see above). Starts on `/Login` (`UserOptions.cs:5`), opened with `scene.OpenAsync("/Login")`, not recorded.
The fields are **Username or email address** and **Password** (`Views/LoginFormCredentials.cshtml:7,13`), named
`LoginForm.UserName` and `LoginForm.Password`; the button is **Log in** (`Views/LoginForm.Edit.cshtml:9`).
The wrong password is the user name itself: type `jamie` in the Password field. It differs from the generated password,
and it is not a credential.

`lock-1` (about 9 seconds)
- Type `jamie` in `[name='LoginForm.UserName']` and `jamie` in `[name='LoginForm.Password']`; click **Log in** with
  `ClickAndWaitForNavigationAsync`. Wait for the text `Invalid login attempt.` (`AccountController.cs:206`).
- Visible when the narration ends: the **Log in** form with the user name `jamie` and the message "Invalid login attempt.".

`lock-2` (about 14 seconds)
- Repeat until the page shows `The account is locked out` (`AccountController.cs:192`): type `jamie` in the Password field
  (type the user name again if the field was cleared), click **Log in**, wait for either `Invalid login attempt.` or
  `The account is locked out`. Do not count the attempts: stop on the lockout message; if it does not appear after eight
  attempts in all, stop and see `OPEN-QUESTIONS.md`.
- Visible when the narration ends: the message "The account is locked out". After this answer the controller renders the
  page without its form (`AccountController.cs:195`): that is expected.

## Clip `06-unlock` (chapter 06, steps `unlock-1`, `unlock-2`)

Signed in as `admin` (`state.json`). Starts on `/Admin/Users/Index` (`AdminController.cs:28`), opened with
`scene.OpenAsync("/Admin/Users/Index")`, not recorded, **within five minutes of the lockout**.

`unlock-1` (about 9 seconds)
- Highlight the `jamie` row, on the red **Locked** badge (`Views/UserFields.cshtml:14-18`). Click the row's **Actions**
  button (`button.actions` in the row; text **Actions** or an ellipsis, `AdminListActions.cshtml:31`).
- The page is already open when the capture starts, and the narration describes the list instead of opening it. The row
  also carries an **Unconfirmed** badge (`Views/UserFields.cshtml:8-13`), because the email of `jamie` is not confirmed:
  leave it, the narration names only the **Locked** badge.
- Visible when the narration ends: the open Actions menu of `jamie`, with **Unlock** among its items
  (`Views/UserActionsMenu.cshtml:29`).

`unlock-2` (about 8 seconds)
- Click **Unlock**. The confirmation dialog shows the title "Unlock user" and the text "Are you sure you want to unlock
  this user?" (`UserActionsMenu.cshtml:29`); click **Ok** (`#modalOkButton`, `OrchardCore.Themes/TheAdmin/Assets/js/TheAdmin/TheAdmin.ts:30`,
  label from `TheAdmin/Views/Layout.cshtml:99`) and wait for the Users list to load again.
- Visible when the narration ends: the Users list with the notification "User unlocked successfully."
  (`AdminController.cs:633`) and the `jamie` row without the **Locked** badge.

## Checks for private data

- Only the invented user `jamie` and `jamie@example.com`, and `admin@example.com`, appear. No other user exists on the site.
- The admin password and the `VIDEO_PASSWORD` value are never typed on camera. The password generated in `rules-3` is random,
  made on the throwaway site, and the site is removed afterwards.
- `Program.cs` of the checkout, `state.json`, `signed-out.json` and the copies of `App_Data` stay out of git.
- OCR the video (one frame per second and at every scene change) for real names, addresses and tokens, as `SKILL.md` asks, and
  check that no browser notification, bookmark bar or address bar with a private host is in the frame.
