# Recording plan: Create an Orchard Core theme

An audience of developers: most of the video is slides (`slides.py`), drawn without a browser. Only one chapter is a
recording, the clip `05-apply`: the Themes page of the admin, then the front end. Everything below the clip is what a
person needs to make that one recording without deciding anything.

The recording shows a theme that the viewer builds in the slides (`MyTheme.OrchardCore`). The browser cannot tell
whether that theme was generated by `dotnet new octheme` or written by hand, so the recording uses a copy of the
generated files inside an Orchard Core checkout. That keeps every label of the admin identical to the source the
narration was checked against.

## The site it needs

### Orchard Core

- A throwaway checkout of `OrchardCMS/OrchardCore` at commit `92db4a837d` (the commit the labels in this plan were read
  from, and that `catalog/SOURCE.md` names), outside this repository. Do not use a `dotnet new occms` site: it pulls a
  published package version, whose labels may differ from the source.
- Build it with the .NET SDK that the checkout requires. Stop the site before building it again.

### The theme project (written by hand, outside the capture)

Create `src/OrchardCore.Themes/MyTheme.OrchardCore/` in the checkout with exactly these files. They are what
`dotnet new octheme -n "MyTheme.OrchardCore"` creates (`OrchardCore.Templates.Theme/OrchardCore.Templates.Theme.csproj`),
with three changes: the four package references of the template are replaced by the project references that the other
themes of the checkout use (`src/OrchardCore.Themes/TheTheme/TheTheme.csproj` has the same SDK and property, and the
same four project references among others), the target framework is left out because the `Directory.Build.props` and
`Directory.Build.targets` of `src/OrchardCore.Themes` give one and apply the theme targets, and the manifest is edited
as the slide `manifest-1` shows. `Nullable` and `ImplicitUsings` are left out too: the theme has no code other than the
manifest.

`MyTheme.OrchardCore.csproj`

```xml
<Project Sdk="Microsoft.NET.Sdk.Razor">

  <PropertyGroup>
    <AddRazorSupportForMvc>true</AddRazorSupportForMvc>
  </PropertyGroup>

  <ItemGroup>
    <FrameworkReference Include="Microsoft.AspNetCore.App" />
  </ItemGroup>

  <ItemGroup>
    <ProjectReference Include="..\..\OrchardCore\OrchardCore.Theme.Targets\OrchardCore.Theme.Targets.csproj" />
    <ProjectReference Include="..\..\OrchardCore\OrchardCore.ContentManagement\OrchardCore.ContentManagement.csproj" />
    <ProjectReference Include="..\..\OrchardCore\OrchardCore.DisplayManagement\OrchardCore.DisplayManagement.csproj" />
    <ProjectReference Include="..\..\OrchardCore\OrchardCore.ResourceManagement\OrchardCore.ResourceManagement.csproj" />
  </ItemGroup>

</Project>
```

`Manifest.cs`

```csharp
using OrchardCore.DisplayManagement.Manifest;

[assembly: Theme(
    Name = "MyTheme",
    Author = "Jamie Chen",
    Website = "https://example.com",
    Version = "0.0.1",
    Description = "A first theme with a plain layout.",
    Tags = ["Starter"]
)]
```

`Views/Layout.liquid` (the file of the template, unchanged)

```liquid
<!DOCTYPE html>
<html lang="{{ Culture.Name }}">
<head>
    <meta charset="utf-8">
    <title>{% page_title Site.SiteName, position: "before", separator: " - " %}</title>

    {% resources type: "Meta" %}

    <!-- INSERT REQUIRED RESOURCES HERE -->

    {% resources type: "HeadLink" %}
    {% resources type: "Stylesheet" %}
    {% resources type: "HeadScript" %}
</head>
<body dir="{{ Culture.Dir }}">

    {% render_body %}

    <footer>
    {% render_section "Footer", required: false %}
    </footer>

    {% script name:"jquery", use_cdn:"true", at:"Foot" %}

    {% resources type: "FootScript" %}
</body>
</html>
```

`wwwroot/Theme.png`: the thumbnail of the card, made once outside this repository (never copy the thumbnail of another
theme: it would look the same as the card of that theme on the same page). Create the folder, then run, from inside it:

```bash
mkdir wwwroot && cd wwwroot
python -c "from PIL import Image, ImageDraw, ImageFont; im = Image.new('RGB', (1200, 800), (29, 91, 54)); ImageDraw.Draw(im).text((600, 400), 'MyTheme', font=ImageFont.load_default(size=140), fill=(255, 255, 255), anchor='mm'); im.save('Theme.png')"
```

Then add the theme to the web application, in `src/OrchardCore.Cms.Web/OrchardCore.Cms.Web.csproj`, next to the other
project references:

```xml
<ProjectReference Include="..\OrchardCore.Themes\MyTheme.OrchardCore\MyTheme.OrchardCore.csproj" />
```

Build `src/OrchardCore.Cms.Web` once to be sure the theme compiles.

### Running it

- Auto Setup (`src/OrchardCore.Cms.Web/Program.cs` calls `AddSetupFeatures("OrchardCore.AutoSetup")`), so no setup or
  sign-in form is recorded. Environment variables, with an empty folder outside both repositories for
  `ORCHARD_APP_DATA`:

  ```bash
  export ORCHARD_APP_DATA=<empty folder outside both repositories>
  export OrchardCore__AutoSetup__Tenants__0__ShellName=Default
  export OrchardCore__AutoSetup__Tenants__0__SiteName="Orchard Core"
  export OrchardCore__AutoSetup__Tenants__0__SiteTimeZone=America/Los_Angeles
  export OrchardCore__AutoSetup__Tenants__0__AdminUsername=admin
  export OrchardCore__AutoSetup__Tenants__0__AdminEmail=admin@example.com
  export OrchardCore__AutoSetup__Tenants__0__AdminPassword=<password>
  export OrchardCore__AutoSetup__Tenants__0__DatabaseProvider=Sqlite
  export OrchardCore__AutoSetup__Tenants__0__RecipeName=Blog
  export HTTP_PROXY=http://127.0.0.1:9 HTTPS_PROXY=http://127.0.0.1:9
  export ASPNETCORE_ENVIRONMENT=Development ASPNETCORE_URLS=http://localhost:5010
  dotnet run --project src/OrchardCore.Cms.Web --no-launch-profile
  ```

  `<password>` is the password chosen outside git, the same as `VIDEO_PASSWORD`. The first request sets the site up
  (a few seconds).
- Recipe: Blog. It enables `OrchardCore.Themes` (the Design, Themes page), `TheBlogTheme` and `TheAdmin`, and sets
  `TheBlogTheme` as the site theme and `TheAdmin` as the admin theme (`TheBlogTheme/Recipes/blog.recipe.json`,
  steps `feature` and `themes`).
- Features to enable before recording: none. Do not enable `MyTheme.OrchardCore` yourself: the clip does it.
- Settings: none. External services: none (the proxy variables above keep every outgoing call away).
- Seed data: none beyond the content of the Blog recipe. The theme project above is the only addition.
- Checks before the first take: `http://localhost:5010/MyTheme.OrchardCore/Theme.png` answers with the green picture
  (the Themes page builds the thumbnail URL from the theme identifier, `ThemeEntry-Thumbnail.SummaryAdmin.cshtml:6`),
  and `/Admin/Themes` lists a card titled `MyTheme` with the buttons `Make Current` and `Enable`.

### Sign-in

In Git Bash on Windows, set `MSYS_NO_PATHCONV=1` for every `Recorder` command, or a path such as `/Admin` is turned
into a Windows path.

Recorder variables: `VIDEO_ROOT` (the folder of this video), `VIDEO_BASE_URL=http://localhost:5010`,
`VIDEO_USER_NAME=admin`, `VIDEO_PASSWORD` (the password chosen outside git). Run `Recorder setup` once; it saves
`state.json` (git-ignored). No mask script is needed: the site is made from scratch and holds no real names.

## Order and snapshots

Only one clip is recorded, `05-apply`, so there is no order between clips.

`05-apply` changes the site: it enables `MyTheme.OrchardCore` and makes it the site theme. Snapshot before the first
take: after Auto Setup has run and `Recorder setup` has written `state.json`, stop the site, copy the
`ORCHARD_APP_DATA` folder and `state.json` aside, and start the site again. **Restore that copy before every new take**
(stop the site, restore, start): a second take on the changed site would not show the message `MyTheme was enabled`,
and `MyTheme` would already be the current theme.
